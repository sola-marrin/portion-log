# ポーションログ

毎食のポーション（カテ1・カテ2・脂質）を記録して、1日分を1枚の画像にまとめ、コーチに報告するスマホ向けWebアプリです。
「食事ログ」をもとにした別のアプリです。食事ログはそのまま残し、こちらは別のリポジトリで公開します。

## 食事ログとの違い・分け方
- アイコンは紫。名前は「ポーションログ」。
- 記録の保存先（IndexedDB `portionLog`、localStorage `portionLog.*`）とオフライン用の保存（`portion-log-v1`）は、食事ログと別。同じGitHubアカウント（同じドメイン）で両方を公開しても、記録は混ざらない。
- バックアップのファイル名は `portion-log-backup-日付.json`。食事ログのバックアップファイルも読み込める（ポーションの記録がない食事として入る）。

## ポーション（ポーションコントロールガイドのルール）
- 区分は「朝・昼・夕・間食💀」の順。記録の中では、夕は今までどおり「夜」として保存している（前の記録もそのまま使える）。間食は「できるだけ食べない」が前提なので、時間で自動的に選ばれることはない（自分で選べば入力できる）。間食には目標がなく、合計だけ出す。
- 「ポーションを変更」で、朝・昼・夕それぞれの カテ1・カテ2 のポーションを、使う人が自分で入れる（はじめて使うときは自動で開く）。脂質は毎食15g以下で固定。
- 記録では、食品名・量・ポーション（kcalを入れると80kcal＝1pで計算）・脂質（カテ2のみ）を入れて「カテ○に食品を追加」。食事ができたら「この食事を保存」。保存すると入力欄は空になり、区分は次へ進む（朝→昼→夕。間食のあとは時間で決める）。修正を保存したときは進めない。
- 保存・削除のあと、画面の下に7秒ほど「元に戻す」が出る。新しく保存した記録を元に戻すと、記録は消えて入力欄に戻る（直してから保存し直せる）。修正は修正の前に、削除は削除の前に戻る。
- 「カテ○に食品を追加」を押すと、ボタンの下に「追加しました」と出て、追加した行が一瞬光る（画面は動かさない）。
- カテの色：カテ1＝赤寄りのピンク、カテ2＝オレンジ（どちらもテキストに合わせる）。記録欄のカテ1／カテ2の選択、「カテ○に食品を追加」ボタン（選んでいるカテの色。うすいぬり＋カテの色の枠）、食品一覧の「カテ1」「カテ2」の札、よく使う食品のボタンと札、まとめ画像の合計で使う。青・赤・緑は「足りない・オーバー・目標どおり」に使っているので、カテの色には使わない。「この食事を保存」は自分の色のまま。
- 「前回と同じ」（「カテ1・カテ2」の右はしの小さな文字ボタン）：選んでいる区分の、最近の食事（中身が同じものは1つにまとめて、5つまで）から選ぶと、カテ1/2の食品と「その他」が入る。写真と時間は入らない。入れたあとは、食品をタップして直す・×で消す・食品を足すことができる。すでに入力があるときは、入れ替えてよいか聞く。
- 記録欄の説明は「kcalを入れると、80kcal＝1pで計算します。」。その下の「調べる：」にリンクが2つ：文部科学省「食品成分データベース」（広告なし。食品のページで重さを入れて「重量変更」を押すと、その量のカロリーと脂質が出る）と、カロリーSlism。どちらも、入れた食品名で検索した状態で開く。
- ポーションは0.1p単位で四捨五入（1.25p → 1.3p、1.24p → 1.2p）。ご飯も同じ。
- 「よく使う食品」に登録しておくと、タップで入力欄（カテ・食品名・量・ポーション・脂質）に転記される（すぐには追加しない）。量を「50g」のようにgで登録しておくと、量を「120g」に変えたときにポーションと脂質を計算し直す（例：ご飯50g＝1p → 120g＝2.4p）。確かめてから「カテ○に食品を追加」。
- 「その他でよく使う食品」：「その他」によく書く言葉を、タップで入れられる（ポーションは付かない）。
- 食べ始めは自動で入る。食べ終わりは、一覧の「食べ終わった」ボタン（押すとその場で保存）か、記録欄の「食べ終わり」に手で入れる。
- 「ポーション計算」：記録欄の「ポーション」の横の「計算」で、画面の下から開く。商品の栄養成分表示（100gあたり・1袋あたり・1本あたりなど）のカロリーと脂質を入れると、1ポーション（80kcal）が何g・何袋かを出す。
  - 「食べる量から」：食べる量（表示の単位か、1袋のgが分かればgでも）を入れると、何ポーションか（0.1p単位で四捨五入）とkcal・脂質を出す。
  - 「ポーションから」：食べたいポーションを入れると、どれだけ食べればよいか（gや袋）とkcal・脂質を出す。選んでいるカテの足りない分（目標−入力中の食品）を、最初から入れておく（自分で入れた数は変えない）。
  - 「記録に転記」で、量・kcal・ポーション・脂質を記録欄に入れて閉じる（食品名とカテは自分で選ぶ）。計算の数値は残るので、もう一度「計算」で続きからやり直せる。新しい商品は上の「リセット」から。計算の数値は、アプリを閉じると消える。
- 書きかけの記録：「この食事を保存」を押す前の入力（写真・区分・時間・カテ1/2の食品・その他・入力中の食品）は、入力するたびに自動でスマホに残す。アプリを閉じても、次に開いたときに戻り、「書きかけの記録を戻しました」と出る（「消す」で消せる）。修正中の記録も同じ。保存したとき・「やめる」を押したときに消える。書きかけがあるのに日付やカレンダー、別の記録の「修正」を押すと、「保存せずに消してよいですか？」と聞く。書きかけはバックアップには入らない。
- ポーションの表（「この日のポーション」と、記録中の食事のポーション）：カテ1・カテ2・脂質を1行ずつ、「いま／目標／判定」の表で出す（数字は小数1けた）。目標どおり（±0.5p未満）はうすい緑、足りないときは青の文字と枠（「あと○p」）、オーバーのときはぬりつぶしの濃い赤に白い文字（「○p多い」「○gオーバー」。カテ1のピンクと見分けるため）。脂質は15g以下ならOK。間食は「いま」だけ。
- 記録中の食事のポーションは、入力中の食品だけを数える（同じ区分の保存ずみの記録は足さない）。目標があれば、何も入れていなくても 0.0p から出す。1日の合計は「この日のポーション」で見る。
- カレンダー：記録がある日は色がつく。朝・昼・夜がすべて記録されていて、どれもカテ1・カテ2が目標どおり・脂質15g以下の日には「○」がつく（間食は見ない）。「最近の記録（3日分）」はなくした（カレンダーで同じことができるため）。
- 食品の表記（「この日の食事」の一覧・記録欄・まとめ画像）：「ささみ 100g（1.5p／脂質:0.3g）」の形。量は記録欄の「量」に入れたもの（空なら名前だけ）。
- まとめ画像：時間は写真の上。食品は1品ずつ1行。その下に、自分の色で合計を2行：1行目［合計］［カテ1］○p、2行目［カテ2］○p 脂質○g（カテ2はカテ1の位置にそろえる）。合計の［カテ1］と数値はカテ1の色、［カテ2］と数値・脂質はカテ2の色。［合計］は自分の色。その下に、その他（野菜・汁物など）を通常の文字色で。合計は朝・昼・夜（間食）ごと。目標は画像に入れない。
- 食後のお知らせ（画面の上に1行だけ。夕のあとは出さない）：〜4時間「あと○時間○分で【脂肪が燃え始めます！】」、4〜5時間「【脂肪燃焼中！！】」、5〜6時間「【脂肪燃焼中！！】まもなく次の食事」、6〜7時間「まもなく次の食事」（4〜6時間が脂肪燃焼タイム）。説明文は出さない。スマホのお知らせがまだオフのときだけ、小さな「オンにする」ボタンを出す。お知らせを許可すると、4時間と5時間で通知も出す。ただし、通知用のサーバーがないため、アプリを閉じている間は通知が出ないことがある（開いたときに画面の上に出る）。iPhoneは、ホーム画面に追加したアプリから開いたときだけ通知を許可できる。
- テーマの色の「ピンク」は、カテ1のピンクと見分けるため、赤むらさき寄り（色相328）。前のピンク（344）を選んでいた人も、自動でこちらになる。
- 小さな文字ボタン（「消す」「前回と同じ」など）と×ボタンは、指で押しやすい高さ（44px）にしている。
- バックアップには、ポーションの設定とよく使う食品も入る（version 2）。読み込み時、よく使う食品は同じ名前がないものだけ足し、ポーションはその端末で未設定のときだけ入れる。

## ファイル
- `index.html` … アプリ本体（HTML/CSS/JS、1ファイル完結）
- `sw.js` … オフラインで使うための部品（Service Worker）
- `manifest.webmanifest`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png` … ホーム画面に追加するための設定とアイコン

## GitHub Pagesで公開する手順
1. GitHubで新しいリポジトリを作る（例: `portion-log`。食事ログとは別のリポジトリにする）。
2. このフォルダの中身（6ファイル）をすべてアップロードする。
3. リポジトリの **Settings → Pages** を開く。
4. **Source** を「Deploy from a branch」、**Branch** を `main` / `/ (root)` にして保存する。
5. 数分後、`https://（ユーザー名）.github.io/（リポジトリ名）/` で開ける。

## 使う人への案内（ホーム画面に追加）
- iPhone: Safariで開く → 共有ボタン → 「ホーム画面に追加」
- Android: Chromeで開く → メニュー → 「ホーム画面に追加」または「アプリをインストール」
- 以後はホーム画面のアイコンから開く。LINEやチャットワーク内で開くと別の保存領域になり、記録が見えなくなることがある。

## データについて
- 記録は、使う人のスマホのブラウザ（IndexedDB）にだけ保存される。作者や他の人には見えない。GitHubにも送られない。
- 容量は、スマホの空き容量しだい（以前の約5MBよりずっと大きい）。
- 以前のバージョン（localStorage）で記録がある場合は、初めて開いたときに自動でIndexedDBへ移す。元のデータは消さずに残る。
- ブラウザのデータを消す、機種変更をすると記録は消える。そのため、画面の一番下の「バックアップ」で、ときどき記録をファイルに書き出しておく（目安は、2週間に1回）。

## バックアップ（書き出し・読み込み）
- 画面の一番下の「バックアップ」から、「記録を書き出す」で、全部の記録（写真・食べたもの・よく食べるもの）を1つのファイル（`portion-log-backup-日付.json`）に保存できる。共有メニューが出る機種では、「ファイルに保存」などを選んで、クラウドや「ファイル」アプリなど、なくさない場所に置く。
- 「記録を読み込む」で、そのファイルを選ぶと、記録が戻る。機種変更のときや、記録が消えたときに使う。
- 読み込みは「足し算」: すでにある記録は消えない。同じ食事（同じ記録のID）は、重複しない。同じファイルを何度読み込んでも、増えない。
- Claude版（公開ページ）で書き出したファイルも、GitHub版で読み込める。ファイルの形式は同じ。
- 14日以上、書き出していないと、画面の表示の色が変わって、知らせる。
- 「端末の使用量」は、このアプリがスマホに保存しているデータの大きさの目安。

## オフライン
- 一度インターネットにつないで開くと、アプリがスマホに保存され、電波がなくても開ける（撮影、記録、画像の保存もできる）。
- フォント（Zen Maru Gothic）は、一度つないだときに保存される。それまで・保存されていないときは、スマホ標準のフォントで表示される。
- 更新したとき: 電波があれば、開くたびに最新の `index.html` を取りに行く。電波がなければ、保存済みのものを使う。
- アイコンなど `index.html` 以外のファイルを変えたときは、`sw.js` の `CACHE = 'portion-log-v1'` を `v2` のように1つ上げると、みんなのスマホで入れ替わる。

## 更新するとき（記録を残すために）
- 記録は、アプリのURLと開き方ごとに、スマホの中に保存されている。更新は、**同じリポジトリのファイルを上書き**して行う（新しいリポジトリを作らない）。URLが変わると、これまでの記録は見えなくなる。
- 更新しても、これまでの記録はそのまま残る。古い形式の記録は、初めて開いたときに自動で新しい保存先へ移る（元のデータは消さずに残る）。
- **ホーム画面のアイコンは、消さない。** iPhoneでは、アイコンを消すと、そのアプリの記録も一緒に消える。新しいアイコンにしたいだけの場合は、古いアイコンのままで使い続けてよい（新しく使い始める人は、新しいアイコンになる）。
- ブラウザの「閲覧データ（サイトデータ）を消去」はしない。記録が消える。

## 保存の仕組み（Claude版との違い）
- 「画像を保存」は、共有メニュー（Web Share）が使える端末ではそこから「画像を保存」を選べる。使えない場合は通常のダウンロードになる。
- 保存できないときは、画像を長押しして「写真に保存」。
